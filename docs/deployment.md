# Деплой на бесплатный тариф Render

Dicebound рассчитан на размещение без обязательных платежей: три сервиса Render
и ни одного платного инстанса. Конфигурация описана в `render.yaml` в корне
репозитория — инфраструктура как код, секреты в Git не хранятся.

## Состав

| Сервис          | Тип Render  | Что запускает                                 | Тариф |
| --------------- | ----------- | --------------------------------------------- | ----- |
| `dicebound-api` | Web Service | `node apps/api/dist/combined.js` — HTTP + бот | free  |
| `dicebound-web` | Static Site | собранный `apps/web/dist`                     | free  |
| `dicebound-db`  | PostgreSQL  | база игры                                     | free  |

## Почему API и бот в одном процессе

Render не предоставляет бесплатных background-воркеров: бесплатный инстанс
возможен только для web-сервиса, статического сайта, PostgreSQL и Key Value.
Бот работает на long polling и **не порождает входящих запросов**, поэтому
отдельный сервис с ботом простаивает с момента старта и Render усыпляет его
через 15 минут без входящего трафика.

Решение — совмещённый процесс `apps/api/src/combined.ts`: Fastify слушает HTTP
(и проходит healthcheck), а бот работает рядом с ним в том же процессе и не даёт
инстансу уснуть. Обе части используют один пул соединений с базой.

Порядок запуска в `combined.ts` намеренный: **сначала HTTP, потом бот**.
Платформа проверяет здоровье сервиса по порту, а подключение к Telegram может
занимать секунды или упасть на настройках BotFather. Если слушать бота раньше,
сервис не откроет порт и деплой не пройдёт healthcheck.

Каждая часть по-прежнему запускается отдельно через свой `index.ts`:
`npm start -w @dicebound/api` и `npm start -w @dicebound/bot`.

## Порядок развёртывания

1. Подключите репозиторий к Render и создайте Blueprint из `render.yaml`.
2. Задайте в панели Render значения, помеченные `sync: false`:
   - `BOT_TOKEN` — токен из BotFather (секрет);
   - `APP_SHORT_NAME` — короткое имя Mini App из `/newapp`, не имя бота;
   - `CORS_ORIGINS` — адрес статического сайта, который выдаст Render
     (например `https://dicebound-web.onrender.com`);
   - `VITE_API_ORIGIN` — адрес API для сборки статики
     (например `https://dicebound-api.onrender.com`).
3. Укажите в BotFather адрес Mini App на домен статического сайта.

После первого деплоя Render выдаст обоим сервисам адреса вида
`*.onrender.com`; впишите их в `CORS_ORIGINS` и `VITE_API_ORIGIN` и повторите
деплой.

## Миграции базы

`packages/db/src/generated/` и `dist/` не хранятся в Git, поэтому сборка
обязана выполнять `npm run db:generate` и `npm run build:server` — обе команды
уже входят в `buildCommand` API-сервиса.

Сами миграции применяйте отдельно:

```bash
DATABASE_URL=<адрес базы> npm run db:migrate
```

`prisma migrate deploy` идемпотентен и не откатывает данные.

## Ограничения бесплатного тарифа

Эти ограничения накладываются платформой, а не проектом:

- **Web-сервис засыпает** через 15 минут без входящих запросов и просыпается
  около минуты. Первый запрос после простоя будет медленным.
- **750 инстанс-часов в месяц** на рабочее пространство. Один постоянно
  работающий сервис расходует около 730 часов, поэтому второй постоянно
  включённый web-сервис в тот же бюджет не помещается.
- **Бесплатная PostgreSQL живёт 30 дней** и затем удаляется вместе с данными.

## База данных

Бесплатная база Render подходит только для демонстрации: через 30 дней прогресс
игроков будет удалён. Для долгоживущего проекта задайте внешний
`DATABASE_URL` (Neon, Supabase или собственный сервер) и удалите блок
`databases` из `render.yaml`.

Код к провайдеру не привязан: Prisma работает через `@prisma/adapter-pg`,
поэтому подходит любой совместимый с PostgreSQL хост. Параметр `?schema=public`
в строке подключения задаёт `search_path`.

## Резервная копия в личных сообщениях

Пока база на бесплатном тарифе Render, копирование обязательно: через 30 дней
данные удаляются. Задайте `BACKUP_CHAT_ID` — бот будет присылать полный дамп
базы файлом в личные сообщения админа, а восстановить его можно командой
`npm run db:restore`. Порядок и ограничения — в
[резервной копии базы](backup.md).

## Переменные окружения

| Переменная              | Назначение                                                   | По умолчанию      |
| ----------------------- | ------------------------------------------------------------ | ----------------- |
| `RUN_BOT`               | Поднимать ли бота внутри процесса API                        | `false`           |
| `APP_SHORT_NAME`        | Короткое имя Mini App; обязательно при `RUN_BOT=true`        | —                 |
| `CORS_ORIGINS`          | Происхождения фронтенда через запятую; пусто — CORS выключен | —                 |
| `TRUST_PROXY`           | Доверять `X-Forwarded-*` от прокси платформы                 | `false`           |
| `VITE_API_ORIGIN`       | Происхождение API, встраивается в бандл на этапе сборки      | —                 |
| `BACKUP_CHAT_ID`        | Личные сообщения админа для копий; пусто — выключено         | —                 |
| `BACKUP_INTERVAL_HOURS` | Период резервного копирования в часах                        | `6`               |
| `HOST`, `PORT`          | Адрес и порт HTTP; `PORT` на Render подставляет платформа    | `0.0.0.0`, `3001` |

`TRUST_PROXY=true` нужен за обратным прокси: без него rate-limit по IP видит
адрес прокси и считает квоту общей для всех клиентов.

`VITE_API_ORIGIN` встраивается в бандл при сборке, поэтому секретом не
является. Пустое значение сохраняет относительные пути `/api/...` — вариант для
раздачи статики тем же сервисом.

## Проверка деплоя

```bash
curl https://<адрес API>/health/live    # {"status":"ok"}
curl https://<адрес API>/health/ready   # {"status":"ready"} или 503 без базы
```

`/health/live` не ограничен по частоте запросов и используется Render для
healthcheck. `/health/ready` возвращает 503, если база недоступна.

CORS проверяется предзапросом:

```bash
curl -i -X OPTIONS https://<адрес API>/api/hub \
  -H "Origin: https://<адрес сайта>" \
  -H "Access-Control-Request-Method: GET" \
  -H "Access-Control-Request-Headers: authorization"
```

В ответе ожидается `access-control-allow-origin` с адресом сайта. С
неперечисленного происхождения этот заголовок не возвращается.
