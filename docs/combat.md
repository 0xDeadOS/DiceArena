# Контракт боя: тренировка и экспедиции

Источник требований — v2.0. **Это первый игровой вертикальный срез, не законченный баланс MVP.** Там, где v2 не задавал точный порядок или значения, ниже явно зафиксированы выбранные правила прототипа. Их можно пересмотреть до запуска обычных экспедиций, но изменения должны сопровождаться тестами и миграцией уже сохранённых состояний.

Код: `packages/game-core/src/{catalog,enemies,combat,maps}.ts`. RNG/транзакции: `packages/db/src/{random,game}.ts`. Ядро не зависит от БД, часов или генератора случайности.

## Тренировочный поход

- Режим `TRAINING` создаёт только сервер: игрок не может передать режим, seed, уровень или признак усиленных наград, и такие поля отбрасываются валидацией запроса.
- Вход бесплатный при любом запасе бодрости: `storedVigor` не меняется, `hasVigorBoost = false`. Хаб по-прежнему восстанавливает бодрость по UTC для будущих режимов.
- Обычная экспедиция (`EXPEDITION`) использует тот же контракт боя: те же четыре решения, сохранённая грань, один переброс и те же эффекты. Отличаются только цена входа, масштаб противника и награды — см. [docs/expeditions.md](expeditions.md).
- Одновременно один активный поход на `(user, room)`. Снаряжение фиксируется при старте: все шесть граней, качество, аффиксы, база, ilvl и сохранённый PS. Последующие изменения предмета не меняют текущий бой.
- Начальное/максимальное здоровье `50 + S7`. Здоровье переносится между узлами; щиты, яд, слабость, концентрация и перебросы инициализируются заново для каждого боя.
- Карта содержит старт и семь глубин, всего 13 узлов. На одной глубине не более двух вариантов. Все рёбра ведут ровно на следующую глубину; из каждого узла доступны оба узла следующей глубины, если их два. Порядок левой/правой дорожки определяется секретом карты.

| Глубина | Варианты             |
| ------- | -------------------- |
| 0       | Обитель              |
| 1       | Бой со слизнем       |
| 2       | Сундук / обычный бой |
| 3       | Привал / элита       |
| 4       | Обычный бой / сундук |
| 5       | Привал / элита       |
| 6       | Сундук / привал      |
| 7       | Король костей        |

Посещённый узел нельзя получить повторно, перескочить через глубину или покинуть незавершённый бой. Привал восстанавливает `ceil(maxHP × 0.35)` HP, не превышая максимум. Это бесплатное лечение, **не** будущий Мастер огранки.

### Награды

| Источник                   | Золото | Пыль |
| -------------------------- | -----: | ---: |
| Обычный бой, только победа |      4 |    1 |
| Элита, только победа       |      7 |    2 |
| Босс, только победа        |     12 |    3 |
| Сундук                     |      3 |    1 |
| Старт / привал             |      0 |    0 |

До завершения награда лежит в `accumulatedLoot`, а не в кошельке. Победа над боссом выдаёт 100%. Поражение/подтверждённое отступление выдаёт `floor(gold × 0.4)` и `floor(dust × 0.4)` по отдельности. Начисление, terminal state и ответ на запрос атомарны; повтор не выдаёт награду второй раз. Отступление хранится как `DEFEAT`, а активный бой завершается с тем же outcome; здоровье при отступлении может оставаться положительным.

В тренировке **не выпадают** кубики, сферы, фрагменты печати или материалы сверх золота/пыли. Предметы не теряются. Пыль сохраняется в `RoomMember.facetDust` для будущей Мастерской; тратить её пока нельзя. `tutorialDone` не меняется.

## FSM и решения

```text
AWAITING_ROLL
  └─ ROLL → AWAITING_DECISION с сохранённой гранью
       ├─ REROLL → AWAITING_DECISION с новой сохранённой гранью
       └─ DIRECT / SHIFT / FLIP → разрешение хода
              ├─ оба живы → AWAITING_ROLL следующего хода
              └─ смерть → FINISHED, VICTORY / DEFEAT
```

«Разрешение хода» выполняется **внутри одной транзакции**, не является отдельным клиентским endpoint или сохраняемой промежуточной фазой. Одновременно с ходом меняется `MapRun.revision`.

| Решение  | Эффект                                                                                                      | Концентрация        | Завершает ход |
| -------- | ----------------------------------------------------------------------------------------------------------- | ------------------- | ------------- |
| `DIRECT` | Разыграть сохранённую грань                                                                                 | +1, максимум 3      | Да            |
| `SHIFT`  | STRIKE/PIERCE → GUARD или GUARD → STRIKE; `ceil(эффективное значение исходной грани × эффективность / 100)` | Без изменения       | Да            |
| `FLIP`   | Сразу разыграть грань `7 − face`, со всеми её собственными бонусами                                         | −1; не начисляет +1 | Да            |
| `REROLL` | Списать заряд и сохранить следующий серверный бросок                                                        | Без изменения       | Нет           |

По умолчанию стойка имеет эффективность 50%; S6 **заменяет**, не прибавляет процент. HEAL в стойку не конвертируется. Конверсия использует бонусы исходной грани, затем округление; к результату не добавляются заново бонусы другого типа действия. Слабость применяется к финальному атакующему действию после конверсии: `floor(value × 0.7)`.

На бой выдаётся `1 + S2` перебросов и `min(3, S3)` концентрации. Переброс может дать ту же грань; он не тикает яд, не меняет intent, ход, щиты или HP. Нельзя получить ещё один обычный бросок, уже находясь в `AWAITING_DECISION`. У flip нет второго шага выбора или возможности бесплатно перевернуть грань обратно.

## Порядок эффектов

Для любого коммитящего действия:

1. Списать/начислить концентрацию согласно решению, определить действие, снять старую слабость.
2. Разыграть грань. Лечение ограничено maxHP; щит прибавляется к текущему.
3. При атаке: применить shield bypass и урон; вампиризм от **фактического урона по HP**, не от щита/overkill; яд от PIERCE; ответные шипы врага.
4. Проверить смерть. Если оба умерли, приоритет имеет **поражение игрока**.
5. Тик яда врага → проверка смерти. Затем тик яда игрока → проверка смерти.
6. Исполнить **ранее показанное** намерение врага. Исключение только в значении Shield Bash: базовый урон + щит, оставшийся после действия игрока; такая зависимость прямо обозначена в UI.
7. Проверить смерть. Если бой продолжается: сохранить `floor(остаток щита игрока × S5 / 100)`, перейти к новому ходу и объявить следующий intent.

Таким образом, смертельный удар/яд останавливает дальнейшие фазы. Яд врага может убить его прежде, чем сработает яд игрока. Это выбранный детерминированный порядок, не одновременный тик.

### Урон, щиты и статусы

- Щит поглощает `min(damage, max(0, shield − ignore))`. Непоглощённое наносит HP-урон. Игнорируемая часть щита остаётся, а не уничтожается автоматически.
- PIERCE игнорирует `ceil(enemyShield / 2)` **ёмкости щита**, а не наносит половину урона напрямую. STRIKE игнорирует плоское значение P8.
- Шипы врага срабатывают при STRIKE, если перед атакой у него был щит, в том числе при bypass. PIERCE не провоцирует эти шипы. Отражённый урон идёт непосредственно в HP игрока.
- P6 отражает урон врагу, если перед входящим ударом у игрока был положительный щит. Полностью поглощённый удар тоже отражается. Вампиризм врага применяется до этого отражения.
- Старый вражеский щит и его шипы исчезают непосредственно перед его новым действием; Shield Bash сначала запоминает остаток для расчёта. GUARD затем создаёт новый щит/шипы.
- Яд обходит щит, длится три тика. Новое наложение суммирует величину и обновляет длительность до трёх. Яд S4 накладывается на PIERCE даже при отсутствии HP-урона и тикает в этом же коммитящем действии. Крыса отравляет только при нанесении HP-урона; первый тик — на следующем коммите игрока.
- Слабость живёт до следующего коммитящего решения, в том числе если игрок лечится/защищается. На reroll не снимается; на HP/щит от неатакующего действия не влияет.
- Хроника хранит последние 20 событий. Намерение босса не пересчитывается посреди хода при пересечении порога здоровья.

## Базы, аффиксы и PS

Эффективное значение: `floor((baseValue × (1 + quality / 100) + flat) × (1 + percent / 100))`. Процентные бонусы складываются; rarity-множителя нет.

В этом прототипе выбраны имплиситы: **Bone — без бонуса; Iron — +1 к плоскому щиту; Obsidian — +5% щита**. Значения баз не являются завершённой экономической калибровкой.

| ID  | Эффект                      | T1    | T2    | T3    | Вес |
| --- | --------------------------- | ----- | ----- | ----- | --: |
| P1  | Плоский бонус STRIKE        | 1     | 2     | 4     | 100 |
| P2  | Плоский бонус GUARD         | 1     | 2     | 4     | 100 |
| P3  | % STRIKE и PIERCE           | 10–15 | 16–25 | 26–40 |  80 |
| P4  | % GUARD                     | 10–15 | 16–25 | 26–40 |  80 |
| P5  | Плоский бонус грани 6       | 3     | 6     | 10    |  60 |
| P6  | Шипы при наличии щита       | 2     | 5     | 9     |  70 |
| P7  | Плоский бонус чётных граней | 1     | 2     | 3     |  60 |
| P8  | STRIKE игнорирует щит       | 2     | 4     | 8     |  70 |
| S1  | % вампиризма                | 8     | 14    | 20    |  60 |
| S2  | Дополнительные перебросы    | 1     | 2     | 3     |  50 |
| S3  | Начальная концентрация      | 1     | 2     | 3     |  70 |
| S4  | Яд при PIERCE               | 2     | 4     | 7     |  80 |
| S5  | % сохранения щита           | 20    | 35    | 50    |  50 |
| S6  | % эффективности стойки      | 65    | 75    | 90    |  60 |
| S7  | Дополнительный maxHP        | 8     | 16    | 30    | 100 |

Эти веса используются генератором [Мастерской](workshop.md); правила выбора числа свойств и тиров там описаны отдельно. T1 доступен с ilvl 1, T2 с 10, T3 с 20. Не более двух префиксов и двух суффиксов, без повторов ID; значения проверяются по диапазону тира. NORMAL имеет 0 свойств, MAGIC — 1–2, RARE — 3–4. UNIQUE пока отклоняется как неподдерживаемое боевое снаряжение. Проверяются шесть различных граней 1–6, качество 0–20 и ilvl 1–50.

`calculatePowerScore` сохраняет `10 × ETV`, синергию противоположных разных действий ×1.1 и отсутствие множителя редкости. Низкоуровневая функция принимает пассивный EV явно; Мастерская вызывает автоматический `evaluateDiePowerScore` с документированной временной моделью `ETV_PASSIVE_V1`. Стартовый кубик имеет PS 55. После победы сохраняются `lastVictoryAt` и `lastVictoryPowerScore` из зафиксированного снаряжения, только если `contentVersion` текущего предмета совпадает со снимком. Крафт увеличивает contentVersion и очищает квалификацию. Старые боевые снимки без поля совместимы как версия 0. Тренировочная победа также считается таким использованием; endpoint рейтинга не открыт.

## Шесть врагов

Для обучения HP и величины атак/щитов/лечения/яда/шипов масштабируются как `max(1, round(base × 0.6))`. Проценты вампиризма/слабости не масштабируются. В таблице приведены **уже тренировочные** значения; паттерны повторяются с первого хода.

| Враг             |  HP | Паттерн                                                    |
| ---------------- | --: | ---------------------------------------------------------- |
| Пещерный слизень |  12 | Атака 3 → щит 2 и лечение 2                                |
| Гоблин-копейщик  |  14 | Атака 4 → замах без урона → атака 7                        |
| Чумная крыса     |  11 | Атака 2 + яд 1 при HP-уроне → атака 4                      |
| Каменный страж   |  27 | Щит 6 → толчок `5 + оставшийся щит`                        |
| Кровавый жрец    |  24 | Атака 4 с 50% вампиризма → слабость −30%                   |
| Король костей    |  45 | Атака 5 → щит 5 и шипы 2; новые атаки ниже половины HP — 8 |

Первый узел всегда содержит слизня. Другие обычные бои выбирают из первых трёх типов, элиты — из стража/жреца, последний узел всегда содержит босса. Выбор определяется на сервере и сохраняется вместе с боем.

Масштаб 0.6, лечение привала, конкретные суммы тренировочной добычи и перечисленные соглашения о порядке эффектов — **параметры данного инкремента**. Автотесты доказывают соблюдение этих правил и транзакционных гарантий, но не итоговый баланс обычных экспедиций или рейдов.
