# Рейд Обители и зал славы

Рейд — асинхронное общее событие чата: участники не обязаны быть онлайн одновременно.
Печать собирается совместными вкладами, призванный босс живёт 48 часов, а награда делится
по фактическому вкладу. Зал славы показывает лучшие кубики Обители за последние семь дней.

Все числа ниже — **временные параметры этого инкремента**. Структура задана требованиями
(48 часов, шесть раундов, три рога в сутки, зачёт семь дней), а баланс подобран расчётом
и может меняться; любое изменение требует обновления тестов и миграции сохранённых состояний.

## Печать и призыв

| Параметр                     | Значение                                   |
| ---------------------------- | ------------------------------------------ |
| Цель алтаря                  | 15 фрагментов                              |
| Источник фрагмента           | победа в обычной экспедиции (+1 участнику) |
| Одновременно активных рейдов | 1 на Обитель (частичный уникальный индекс) |
| Длительность рейда           | 48 часов от призыва                        |

Личные фрагменты (`RoomMember.sealFragments`) и алтарь (`Room.sealFragments`) — разные
счётчики: победа начисляет фрагмент участнику, а в алтарь он попадает только явным вкладом
через `POST /api/raid/contribute`. Алтарь не принимает больше цели, остаток остаётся у
участника. Призыв расходует все 15 фрагментов и публикует анонс.

## Босс

| Параметр        | Формула                                                 |
| --------------- | ------------------------------------------------------- |
| Раундов         | 6                                                       |
| HP раунда       | `raidRoundHp(N) = 2N`, где N — число участников Обители |
| Полное HP       | `raidRoundHp(N) × 6`                                    |
| Щит раунда      | `raidShield(r) = ceil(r / 2)` → 1, 1, 2, 2, 3, 3        |
| Рогов в сутки   | 3 на участника (сутки UTC)                              |
| Бросков на удар | 2 (первый + один переброс)                              |

### Почему именно такие числа

Баланс выведен из пропускной способности, а не выбран «на глаз». За 48 часов рейда Обитель
из N участников наносит `3 рога × 2 суток × N = 6N` ударов. Суммарная прочность босса —
`6 × 2N + 12 = 12N + 12`, то есть на один удар приходится `(12N + 12) / 6N = 2 + 2/N`:

| Участников | Прочность босса | Ударов | Нужно за удар |
| ---------- | --------------- | ------ | ------------- |
| 1          | 24              | 6      | 4.0           |
| 2          | 36              | 12     | 3.0           |
| 4          | 60              | 24     | 2.5           |
| 8          | 108             | 48     | 2.25          |

Ориентир снизу — стартовый кубик: его грани дают в среднем 3.67 «сырого» урона
(`STRIKE 4`, `GUARD 5→2`, `STRIKE 6`, `PIERCE 5`, `HEAL 3→0`, `GUARD 7→3`), но часть урона
съедает щит, а грань HEAL тратит рог впустую. Поэтому **одним стартовым кубиком соло-рейд
не добить** — это сделано намеренно: рейд должен требовать развития снаряда, огранки граней
или второго участника. В группе босс падает задолго до того, как кончатся рога.

Щит растёт вдвое медленнее номера раунда: при шести раундах суммарный щит — 12. Линейный
щит (`r`) дал бы 21 и сделал рейд непроходимым даже для сильных кубиков.

## Удар

Удар создаётся одним запросом и сразу содержит серверный бросок: клиент видит грань, но не
видит секретного зерна. Решения три:

| Решение  | Эффект                                                 |
| -------- | ------------------------------------------------------ |
| `DIRECT` | разыграть выпавшую грань как есть                      |
| `SHIFT`  | сменить `STRIKE ↔ GUARD` за 50 % эффективного значения |
| `REROLL` | перебросить грань (один раз на удар)                   |

Переворота грани (`FLIP`) в рейде нет: в одиночном размене нет экономики фокуса, и бесплатный
переворот в известную противоположную грань был бы строго сильнее переброса.

Доля урона от эффективного значения грани (`RAID_ACTION_SHARE`):

| Действие | Доля                              |
| -------- | --------------------------------- |
| `STRIKE` | 100 %                             |
| `PIERCE` | 100 %, игнорирует `ceil(щит / 2)` |
| `GUARD`  | 50 %                              |
| `HEAL`   | 0 %                               |

Урон проходит через то же правило `hit()`, что и в обычном бою: сначала щит, затем здоровье.
Перебор теряется — он не переносится на следующий раунд. Закрытие раунда продвигает фазу и
выставляет щит следующего раунда; закрытие шестого раунда завершает рейд победой.

## Награда и рейтинг

| Параметр                 | Значение                                                                |
| ------------------------ | ----------------------------------------------------------------------- |
| Пул золота               | `40 + 25 × N`                                                           |
| Пул пыли                 | `4 + 3 × N`                                                             |
| Делёж                    | по доле нанесённого урона, округление вниз                              |
| Остаток                  | добирает самый результативный участник, поэтому сумма выплат равна пулу |
| Зачётное окно зала славы | 7 дней                                                                  |

Участники без урона награду не получают. Квалификация кубика в зале славы хранится на самом
предмете (`lastVictoryAt`, `lastVictoryPowerScore`) и сбрасывается любым крафтом, поэтому
рейтинг нельзя надуть изменением артефакта задним числом.

## Анонсы

Игра не обращается к Bot API. Событие кладётся в очередь `GameEvent` **в той же транзакции**,
что и изменение состояния, поэтому анонс не может появиться без факта и не теряется при
повторе команды — `dedupKey` уникален.

| Событие         | Ключ идемпотентности                 |
| --------------- | ------------------------------------ |
| `RAID_SUMMONED` | `raid:<raidId>:summoned`             |
| `RAID_DEFEATED` | `raid:<raidId>:defeated`             |
| `HIGH_PS_CRAFT` | `high-ps:<roomId>:<12-часовое окно>` |

Отправляет отдельный диспетчер в боте (`apps/bot/src/announce.ts`): пачка раз в 15 секунд,
до пяти попыток на событие. Если чат запретил сообщения боту, событие помечается
отправленным и не повторяется — уважение к настройке важнее доставки.

## API

| Метод                       | Назначение                                  |
| --------------------------- | ------------------------------------------- |
| `GET /api/raid`             | алтарь, рейд, открытый удар, права действий |
| `GET /api/leaderboard`      | зал славы Обители за 7 дней                 |
| `POST /api/raid/contribute` | внести личные фрагменты в алтарь            |
| `POST /api/raid/summon`     | призвать рейд (нужен `confirmed: true`)     |
| `POST /api/raid/attack`     | потратить рог и получить бросок             |
| `POST /api/raid/decide`     | `DIRECT` / `SHIFT` / `REROLL`               |

Все мутации требуют заголовок `Idempotency-Key` в формате UUIDv4 и работают в пространстве
имён `raid:v1` с 24-часовым TTL повтора. Рейд защищён собственной ревизией: устаревшее
значение отклоняется кодом `STALE_RAID`, а не молчаливым принятием.

## Гарантии целостности

- Один активный рейд на Обитель — частичный уникальный индекс в базе, а не проверка в коде.
- Один незавершённый удар на участника — второй частичный уникальный индекс.
- Просрочка определяется лениво: рейд без единого удара всё равно становится `EXPIRED`.
- 13 CHECK-ограничений защищают фазу, здоровье, щит, ревизию, число бросков и соответствие
  статуса факту поражения даже при ошибке в коде.
- Секретное зерно удара не покидает сервер; после завершения удара грань обнуляется, а
  действие и значение фиксируются в записи.
